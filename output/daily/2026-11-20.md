### PHP-FPM request smuggling flaw may let unauthenticated attackers run PHP code (CVE-2026-129289)

**HIGH** · Priority 79.75 · US 95% · Europe 95% · MEA 95% · Other 95% · Global IT services 70% · Telecommunications 62% · Vulnerability and exposure management 90% · Secure software delivery and DevSecOps 45%

PHP may not discard unread bytes from an HTTP request body before it reuses a persistent PHP-FPM or LSAPI connection. In PHP-FPM, an unauthenticated attacker can make those bytes form a separate FastCGI request. That request can bypass front-end routing and run attacker-controlled PHP code with the worker&#x27;s privileges. The record does not report exploitation.

Why it matters: Unauthenticated code execution in widely deployed PHP-FPM, without reported exploitation.

Action: Make patching internet-facing PHP-FPM deployments a priority once fixed builds are confirmed. Until then, consider turning off persistent FastCGI connections between the front-end server and PHP-FPM.
