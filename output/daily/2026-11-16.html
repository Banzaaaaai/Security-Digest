The FBI warns that attackers are using ARTEX, an AI-powered penetration testing framework, to automate attacks on organizations worldwide. The warning links the tool to a recent supply-chain breach at ConnectWise that compromised Microsoft 365 customer environments.

HIGH · Priority 80.5

Six unpatched flaws in Danfoss AK-SM800A refrigeration controllers allow unauthenticated takeover

US 65% · Europe 95% · MEA 65% · Other 65% · Logistics 70% · Industrial manufacturing 65% · OT and industrial control systems 95% · Vulnerability and exposure management 80%

Midnight Blue has disclosed six vulnerabilities in Danfoss AK-SM800A refrigeration controllers that could let a remote attacker take over a controller without logging in. No patch is available, and firmware 5.4.0 does not fix the flaws. National cyber agencies in Belgium, Ireland and Germany have issued warnings to operators.

Why it matters: This is a new OT advisory covering unpatched, unauthenticated remote takeover, and government agencies have issued warnings. The source does not report any exploitation.

Action: Find all AK-SM800A units, take them off the internet, and restrict network access to trusted segments until Danfoss releases a fix. Follow the national agency guidance.

Detection assessment: Assessment: OT network monitoring for unexpected access to controller management interfaces is the main option. No rules were provided in the source.

HIGH · Priority 79.5

NoisyTCP Linux kernel flaw allows remote crash of servers in default configurations

US 90% · Europe 90% · MEA 90% · Other 90% · Global IT services 75% · Telecommunications 70% · Vulnerability and exposure management 90% · Zero Trust and cloud security 40%

Researchers have disclosed NoisyTCP, a Linux kernel vulnerability that has existed for about 11 years and affects almost all distributions. Attackers can use it to crash systems running Nginx, Apache or SSH servers with default settings. The source does not report a CVE identifier or any in-the-wild exploitation.

Why it matters: This is a remotely triggerable denial-of-service flaw in widely deployed Linux server infrastructure. The source reports no exploitation in the wild.

Action: List internet-facing Linux servers and track distribution kernel advisories so patches can be applied when available. Because the source does not confirm a CVE or exploitation, check vendor guidance before planning emergency maintenance.

Detection assessment: Assessment: monitoring for unexpected kernel crashes and unusual TCP traffic patterns on internet-facing Linux hosts may surface attempts. The source does not link any detection rules.

Sources: BleepingComputer

Amazon reports attacker AI agents hunting exposed LiteLLM, Dify and One API apps for AI provider keys

US 85% · Europe 85% · MEA 85% · Other 85% · Global IT services 70% · Energy services 50% · AI-assisted work and AI governance 90% · Vulnerability and exposure management 70%

Amazon's threat intelligence team used decoy servers to capture records from attacker-run AI agents. The agents were searching internet-exposed AI apps such as LiteLLM, One API and Dify for stored AI provider API keys. According to the records, stolen keys were used to run the models that powered the search for more keys.

Why it matters: This is an observed campaign stealing credentials from widely used AI gateway software. Evidence comes from decoy servers, and the extent of real-world compromise is not stated.

Action: Find internet-exposed AI gateways and take them off the internet or add access controls, then rotate the stored provider keys. Treat compromise as possible, not confirmed, for any exposed instance.

Detection assessment: Assessment only: monitor AI provider usage for anomalies and check access logs on AI gateways.

HIGH · Priority 78.0

BO Team used Log4Shell in VMware vCenter to compromise a Russian developer's code-signing server

US 85% · Europe 85% · MEA 85% · Other 85% · Global IT services 75% · Energy services 50% · Secure software delivery and DevSecOps 85% · Vulnerability and exposure management 80%

Kaspersky ICS CERT reports that BO Team (also called Black Owl or Hoody Hyena) had access to a Russian software developer's development infrastructure and code-signing server for months. The intrusion started through Log4Shell in VMware vCenter. The developer asked Kaspersky to investigate in June 2025. The source does not say whether any signed software was tampered with or shipped to customers.

Why it matters: Attackers exploited a known flaw in widely used vCenter and compromised code-signing infrastructure. The victim is outside the target regions, and no downstream supply-chain compromise has been confirmed.

Action: Confirm Log4Shell is patched or mitigated on vCenter, and isolate code-signing servers and keys from general infrastructure.

Detection assessment: Assessment only: watch vCenter for JNDI lookup patterns and check signing servers for unexpected signing activity.

Honeypots record scans targeting chained LiteLLM/Starlette flaws CVE-2026-42271 and CVE-2026-48710

US 85% · Europe 85% · MEA 85% · Other 85% · Global IT services 70% · Investment management 55% · Vulnerability and exposure management 85% · AI-assisted work and AI governance 85%

SANS ISC honeypots began receiving requests to the LiteLLM MCP REST endpoint /mcp-rest/test/tools/list over a weekend. The requests appear to be attempts to exploit CVE-2026-42271 and CVE-2026-48710. Horizon3.ai has described how chaining these flaws can give unauthenticated remote code execution. The source reports only scanning and exploit attempts. It does not confirm any successful compromise.

Why it matters: A publicly described unauthenticated RCE chain in widely used AI gateway software is now drawing exploit attempts, as seen in honeypot traffic. Because no successful compromise has been shown, this is rated high rather than critical.

Action: Find all LiteLLM deployments and apply vendor fixes for both CVEs. Remove internet exposure of the MCP REST endpoints, then review logs for probes of that path. Treat any matching requests as attempted exploitation, not confirmed compromise, until host evidence shows otherwise.

CVE-2026-42271 | KEV yes | EPSS 0.91445 | CVSS unknown
CVE-2026-48710 | KEV yes | EPSS 0.70288 | CVSS unknown

Detection assessment: The source links no detection rules. Our assessment is that web and proxy logs should be checked for requests to /mcp-rest/test/tools/list, and LiteLLM hosts should be watched for unexpected child processes.
